# Main Baseline: ArduPilot Timing-Violation Experiments

This branch contains the common baseline used for the ArduPilot timing-violation experiments.

It is based on ArduPilot Copter-4.0 and includes the common logging instrumentation used to collect timing, navigation, and velocity measurements during the simulated mission defined in `way.txt`.

This branch does not represent a specific experimental condition. Each experiment is maintained in a dedicated Git branch containing its own code modifications and a customized `README.md` with the corresponding execution instructions.

## Experiment branches

* **exp/E0-baseline**: Original SITL architecture with logging instrumentation and no interference. This branch represents the original instrumented baseline.

* **exp/E1-direct-dos**: Original SITL architecture under an indiscriminate CPU, cache, and memory saturation workload.

* **exp/E2-separated-sensor**: Modified SITL architecture in which sensor emulation is executed in a separate thread from the main control loop.

* **exp/E3-delay-injection**: Modified SITL architecture with explicit software fault injection. A delay of 30 ms or 50 ms is introduced in the control path for 200 consecutive control cycles when the mission navigation index changes from waypoint 2 to waypoint 3.

* **exp/E4-multicore-interference**: Modified SITL architecture under interference generated by a low-priority cache-contention aggressor.

## Common logging instrumentation

The common logger is implemented in `ArduCopter/Copter.cpp`.

At the beginning of the simulation, the logger creates the file:

```text
exp_log.csv
```

Data is recorded only while the motors are armed, so the resulting CSV covers the active flight phase.

The logger records measurements related to:

* simulation and wall-clock time;
* control-loop timing;
* navigation-state freshness;
* mission navigation index;
* waypoint distance;
* reference and simulated horizontal velocity;
* sensor-producer timing, when supported by the selected experiment.

ArduPilot also produces its native `.BIN` flight logs.

## How to use the repository

1. **Select the experiment branch:**

   ```bash
   git checkout exp/E0-baseline
   ```

   Replace `exp/E0-baseline` with the branch corresponding to the experiment that you want to execute.

2. **Read the branch-specific instructions:**

   Each experiment branch contains a dedicated `README.md`.

3. **Run the experiment:**

   Follow the instructions contained in the selected branch to run the experiment.

4. **Collect the results:**

   Each final experiment is executed three times.

## Repository structure

The `main-baseline` branch contains only the common code and documentation shared by the experiments.

Experiment-specific changes must remain in their corresponding branches. Changes introduced only for one experiment should not be committed to `main-baseline`.
